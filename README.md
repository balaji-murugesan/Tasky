# Tasky: a sandbox for the autonomous delivery loop

A deliberately tiny todo app (React + Express) wired up so agents can take a request from **team chat or a customer email**, write an **OpenSpec** proposal, implement it, **prove it works** (tests + screenshots), open a PR, and have **low-risk PRs merge themselves overnight**.

```
chat / email ──n8n──▶ intake.yml ──▶ issue (agent:ready)
                                          │
                       nightly / on label ▼
                                  agent-build.yml
                         plan: /openspec-propose
                         build: apply → verify loop → screenshots
                                          │
                                          ▼ PR
                                       ci.yml
                 verify · screenshots comment · risk-classify · gate
                       low ──▶ auto-merge     medium/high ──▶ Claude review + human
                                          │
                                          ▼ main
             post-merge.yml (openspec archive PR)   qa.yml (finds bugs → new issues)
                                          │
                              morning-digest.yml ──▶ "12 merged, 2 need you"
```

## Run it locally (5 minutes)

```bash
npm ci
npx playwright install chromium     # or use an installed Chrome: export PW_CHANNEL=chrome
npm run app:up                      # http://localhost:5173
npm run verify                      # typecheck + unit + e2e
npm run screenshots                 # → artifacts/screenshots/
npm run risk -- --files web/src/App.tsx e2e/tasks.spec.ts   # → low
npm run app:down
```

Then open the folder in Claude Code and try: *"Use the ship-change skill on this request: show open tasks before done tasks"* (without GitHub it stops before the PR step).

## Turn on the full loop on GitHub

1. **Push** this folder to a new GitHub repo (private is fine).
2. **Secrets** (Settings → Secrets and variables → Actions):
   - `ANTHROPIC_API_KEY`, or use `claude_code_oauth_token` instead in the workflows if you're on a Claude subscription (`claude setup-token`).
   - `AGENT_APP_ID` + `AGENT_APP_PRIVATE_KEY`: a GitHub App you create (Settings → Developer settings → GitHub Apps) with Contents, Issues, Pull requests: read & write, installed on this repo. **Why:** PRs and labels created with the default `GITHUB_TOKEN` don't trigger other workflows, so CI would never run on agent PRs.
   - `AGENT_GH_TOKEN` (optional): an installation token / PAT so auto-merges trigger `post-merge.yml`.
   - `DIGEST_WEBHOOK_URL` (optional): Slack/Teams/Google Chat incoming webhook.
3. **Repo settings → General**: enable *Allow auto-merge* and *Automatically delete head branches*.
4. **Branch protection on `main`** (Settings → Rules): require a PR, require status checks `verify` and `risk-gate`, block force pushes. Don't require approvals globally; `risk-gate` demands a human approval for medium/high only.
5. **Labels**: `gh label create agent:ready; gh label create agent:building; gh label create needs-human; gh label create do-not-merge; gh label create source:chat; gh label create source:email; gh label create source:qa; gh label create agent:allow-high-risk`
6. **First run**: create issue #1 from `docs/practice-issues.md` and add the `agent:ready` label. Watch Actions.
7. **Intake**: `bash scripts/send-intake.sh chat "Priya" "..."`, then wire n8n with `docs/n8n-intake.md`.

## Map of the repo

| Path | What it is |
|---|---|
| `CLAUDE.md` | Agent operating manual: loop, commands, Definition of Done, rules |
| `.claude/skills/run-app` | Boot / health-check / debug the app |
| `.claude/skills/screenshot-changes` | Capture affected screens, look at them, post to PR |
| `.claude/skills/app-qa` | Exploratory QA → deduplicated bug issues |
| `.claude/skills/intake-to-issue` | Chat/email → buildable issue |
| `.claude/skills/ship-change` | The whole loop for one issue |
| `.claude/skills/openspec-*` | Generated by `openspec init` (don't edit) |
| `.claude/settings.json` | What the agent may and may not run/edit |
| `openspec/` | Specs (source of truth) and change proposals |
| `risk-policy.json` + `scripts/risk-classify.mjs` | What counts as low/medium/high risk |
| `screenshots.config.json` + `scripts/screenshots.ts` | Which screens get captured and how to reach them |
| `scripts/run-app.sh` | Background, idempotent, health-checked app runner |
| `scripts/post-screenshots.sh` | Push PNGs to `pr-screenshots` branch + sticky PR comment |
| `.github/workflows/` | ci, agent-build, qa, intake, post-merge, morning-digest |
